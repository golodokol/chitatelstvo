# ST100 + оплата + webhook — все 18 модулей

Zero Block выбирает **класс + тариф + дату (+ сказку)** → в hidden-поля ST100 попадают `module_id` (1–18), `chosen_stage`, `chosen_tale_number`.

---

## Шаг 1. Три товара в каталоге Tilda

**Каталог** → создайте **3 услуги** (названия **точно** так):

| Название | Цена |
|----------|------|
| Читательство · Разовое | 1 490 ₽ |
| Читательство · Индивидуальное | 1 990 ₽ |
| Читательство · С преподавателем | 4 990 ₽ |

Класс (1–4, 6–8, 9–11) **не** отдельный товар — он в `module_id`.

### 1A. Product ID (обязательно для корзины)

Если при оплате появляется **«Товар не попал в корзину»**:

1. **Каталог** → откройте каждую из 3 услуг
2. Внизу карточки скопируйте **Product ID** (длинное число, например `945818045761`)
3. Пришлите 3 числа — мы пропишем их в `order-config.json` на сервере

**Или** (альтернатива без правки JSON):

1. На главную добавьте **3 блока ST205** (Магазин → карточка товара)
2. В каждом ST205 → **Контент** → **ID товара в каталоге** = Product ID из каталога
3. Блоки можно поставить **внизу страницы** (под ST100) — они связывают каталог с корзиной
4. **Опубликовать** главную

## Шаг 2A. Подробно: поля формы в ST100

Откройте страницу в редакторе Tilda → кликните по блоку **ST100** → **Контент** (или «Редактировать корзину»).

Для **каждого** поля: **+ Добавить поле** → выберите тип → в настройках поля найдите **Variable name** (иногда «Имя переменной») и впишите **точно** как в таблице (латиница, без пробелов, с подчёркиваниями).

**Про дубли полей:** родитель заполняет форму **только в Zero Block** (русские подписи). В ST100 **удалите** поля Your Name / Email / Phone и добавьте **скрытые** (Hidden) поля — тогда в корзине не будет второй английской формы, только товар и «Оплатить».

### Скрытые поля в ST100 (рекомендуем)

Тип **Hidden** / «Скрытое», Variable name **точно** так:

| Variable name |
|---------------|
| `parent_name` |
| `parent_email` |
| `parent_telegram` |
| `child_name` |
| `child_age` |
| `notification_channel` |
| `module_id` |
| `chosen_stage` |
| `chosen_tale_number` |
| `promo_code` |
| `legal_consent` |

Zero Block подставит значения при «Записаться».

### Альтернатива: видимые поля на русском (не Your Name)

| № | Подпись в Tilda | Variable name | Тип в Tilda | Обяз. |
|---|-----------------|---------------|-------------|-------|
| 1 | Имя родителя | `parent_name` | Однострочный текст (Input) | да |
| 2 | Email | `parent_email` | Email | да |
| 3 | Telegram | `parent_telegram` | Однострочный текст | нет |
| 4 | Имя ребёнка | `child_name` | Однострочный текст | да |
| 5 | Возраст ребёнка | `child_age` | Число (Number) | нет |
| 6 | Как присылать новости | `notification_channel` | Выпадающий список (Select) | да |

**Важно про Variable name:** если написать `Parent_name` или `parent-name` — API **не получит** данные. Копируйте из таблицы.

### Select «Как присылать новости»

Variable name: `notification_channel`.

Добавьте **4 варианта**. В Tilda у каждого варианта есть **подпись** (видит родитель) и **value** (уходит в API) — value должны быть **точно** так:

| Подпись (можно по-русски) | value (латиница!) |
|---------------------------|-------------------|
| На email | `email` |
| В Telegram | `telegram` |
| Email и Telegram | `both` |
| Только личная страница | `web` |

> Пока Telegram отключён на сервере (`TELEGRAM_ENABLED=0`), API сам переключит `telegram` → `web`, `both` → `email`.

### Checkbox «Согласие» (обязательно)

1. **+ Добавить поле** → **Checkbox** / «Галочка»
2. Variable name: `legal_consent`
3. Включите **«Обязательное поле»**
4. Текст рядом с галочкой (можно вставить ссылки):

> Я согласен(на) с [политикой конфиденциальности](https://api.chitatelstvo.ru/legal/politika) и [публичной офертой](https://api.chitatelstvo.ru/legal/oferta)

### Кнопка в корзине

В настройках ST100 текст кнопки: **Оплатить** (не «Отправить» и не «Заказать»).

## Шаг 3. Подробно: webhook (после оплаты)

Webhook нужен, чтобы **после успешной оплаты** Tilda отправила данные на ваш сервер → создалась запись ребёнка и пришло письмо со ссылкой на прогресс.

### 3.1. Узнайте WEBHOOK_SECRET

На сервере в файле `/root/chitatelstvo/.env` строка:

```env
WEBHOOK_SECRET=ваша_длинная_случайная_строка
```

Скопируйте **значение** (без `WEBHOOK_SECRET=`). Это пароль между Tilda и API — никому не показывайте на сайте.

### 3.2. Создайте webhook в настройках сайта

1. В редакторе Tilda: **Настройки сайта** (шестерёнка слева или меню проекта)
2. **Формы** → **Webhook** (или «Webhooks»)
3. **+ Добавить webhook**
4. Заполните:

| Поле | Значение |
|------|----------|
| URL | `https://api.chitatelstvo.ru/webhook/register` |
| Метод | POST |
| Заголовок (Header) | Имя: `X-Webhook-Secret` · Значение: *ваш WEBHOOK_SECRET* |

5. Сохраните webhook.

**Проверка URL:** откройте в браузере `https://api.chitatelstvo.ru/webhook/register` — должно показать `ok`. Если ошибка SSL или 404 — сначала почините API.

### 3.3. Подключите webhook к блоку ST100

1. Вернитесь на **страницу** с Zero Block и ST100
2. Кликните блок **ST100** → **Контент** / настройки корзины
3. Найдите раздел **«Webhook»**, **«Отправка данных»** или **«Интеграции»**
4. Выберите созданный webhook (`https://api.chitatelstvo.ru/webhook/register`)
5. Включите **«Отправлять только после оплаты»** / **«After payment only»** — если такой переключатель есть

Без «только после оплаты» заявка может уйти до оплаты — так делать не нужно.

### 3.4. Страница «Спасибо» (Success URL)

**Готово на сервере:** `https://api.chitatelstvo.ru/spasibo`

1. В настройках **ST100** или **корзины** укажите **Success page** / «Страница после оплаты»:
   **`https://api.chitatelstvo.ru/spasibo`**
2. Проверка: откройте URL в браузере — должна открыться страница «Вы в Читательстве!».

*(Опционально: страница `spasibo` на chitatelstvo.ru — см. `TILDA_PAGES.md`.)*

### 3.5. Опубликуйте

**Сохранить** страницу → **Опубликовать** (Publish). Без публикации посетители видят старую версию без ST100.

## Таблица module_id (все модули)

| Класс / группа | Разовое | Индивидуальное | С преподавателем |
|----------------|---------|----------------|------------------|
| 1 класс | 1 | 2 | 3 |
| 2 класс | 4 | 5 | 6 |
| 3 класс | 7 | 8 | 9 |
| 4 класс | 10 | 11 | 12 |
| 6–8 лет | 13 | 14 | 15 |
| 9–11 лет | 16 | 17 | 18 |

**chosen_stage:** `1` = 22 июня, `2` = 20 июля — для **всех** тарифов.

**chosen_tale_number:** `1`–`4` — **только** для разового (module_id нечётные: 1,4,7…).

Zero Block заполняет эти поля автоматически при нажатии «Записаться».

## Шаг 5. Проверка

1. На сайте: 2 класс → Индивидуальное → 22 июня → **Записаться**
2. Корзина: **1 990 ₽**, поля контактов
3. Оплата (тестовая карта Т‑Банка)
4. Письмо на email + `progress_url` в webhook-ответе
5. В CRM Tilda в заявке: `module_id=5`, `chosen_stage=1`

Тест API без Tilda:

```powershell
curl -X POST "https://api.chitatelstvo.ru/webhook/register" `
  -H "Content-Type: application/json" `
  -H "X-Webhook-Secret: ВАШ_СЕКРЕТ" `
  -d "{\"parent_name\":\"Тест\",\"parent_email\":\"test@example.com\",\"child_name\":\"Маша\",\"child_age\":8,\"notification_channel\":\"email\",\"module_id\":2,\"chosen_stage\":\"1\"}"
```

Ответ: `"module_id": 2`, `"module_title": "Индивидуальное обучение, 1 класс"`.

## Если hidden-поля пустые в CRM

1. В ST100 есть 3 hidden с **точными** именами `module_id`, `chosen_stage`, `chosen_tale_number`
2. В Zero Block вставлен актуальный JS (`03-js.txt` или `00-all-in-one.html`)
3. Родитель нажал «Записаться» **после** выбора класса и даты
4. Опубликована **новая** версия страницы
